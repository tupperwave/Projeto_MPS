# UC13 — Gerenciar hosts

| Campo | Descrição |
|---|---|
| **Ator principal** | Administrador ou operador autorizado |
| **Objetivo** | Consultar, listar, atualizar e remover hosts cadastrados |
| **Requisitos relacionados** | RF23, RF24, RF25, RF26, RF20, RF21, RF09 |
| **Pré-condições** | A aplicação foi inicializada |
| **Pós-condições** | A consulta é realizada ou o host é atualizado/removido conforme a operação escolhida |

## Fluxo principal — Consultar e listar hosts

1. O operador acessa o inventário.
2. O sistema consulta os hosts cadastrados.
3. O sistema apresenta a lista de hosts.
4. O operador pode aplicar filtros por endereço IP, hostname, usuário responsável ou tag.
5. O operador seleciona um host.
6. O sistema apresenta os detalhes do host.
7. O sistema encerra o caso de uso sem alterar os dados.

## Fluxo alternativo A — Atualizar host

1. O operador seleciona um host existente.
2. O sistema apresenta os dados atuais.
3. O operador escolhe a opção de atualização.
4. O operador informa os novos dados.
5. O sistema valida as informações.
6. O sistema verifica a existência do usuário responsável, quando aplicável.
7. O sistema preserva o identificador do host.
8. O sistema salva a atualização.
9. O sistema informa o sucesso da operação.

## Fluxo alternativo B — Remover host

1. O operador seleciona um host existente.
2. O sistema apresenta os dados do host.
3. O sistema solicita confirmação explícita.
4. O operador confirma a remoção.
5. O sistema remove o host do inventário.
6. O sistema registra a operação na auditoria.
7. O sistema informa o resultado.

## Exceções

### E1 — Nenhum host encontrado

- O sistema informa que não existem hosts cadastrados ou que nenhum host atende aos filtros informados.

### E2 — Host inexistente

- O sistema informa que o host não foi encontrado.
- Nenhuma alteração é realizada.

### E3 — Dados inválidos

- O sistema informa quais dados são inválidos.
- A atualização não é realizada até que os dados sejam corrigidos.

### E4 — Usuário responsável inexistente

- O sistema informa que o usuário associado não existe.
- A operação é rejeitada.

### E5 — Falha de leitura

- O sistema informa a falha de leitura.
- Os dados não são apresentados como completos ou confiáveis.

### E6 — Falha de escrita

- O sistema informa a falha de persistência.
- A atualização ou remoção não é confirmada como concluída.

### E7 — Cancelamento da atualização

- O operador cancela a operação.
- Nenhuma alteração é realizada.

### E8 — Cancelamento da remoção

- O operador não confirma a remoção.
- O host permanece no inventário.

### E9 — Existência de registros históricos

- O sistema remove o host do inventário, mas preserva os registros de auditoria relacionados.
- O histórico não deve ser apagado automaticamente.

## Regras específicas

- A consulta e a listagem não devem alterar os dados.
- A atualização deve preservar o identificador do host.
- A remoção exige confirmação explícita.
- Falhas de persistência devem ser tratadas sem encerrar abruptamente a aplicação.
- As credenciais do usuário responsável não devem ser exibidas.
- Registros históricos relacionados ao host devem ser preservados.

## Resultado esperado

O sistema deve permitir ao operador realizar as operações de consulta, listagem, atualização e remoção de hosts em um único fluxo de gerenciamento, mantendo validações, confirmações, persistência e auditoria adequadas.
