# UC15 — Manter anotações de hosts e consultar gerentes

| Campo | Descrição |
|---|---|
| **Ator principal** | Administrador ou operador autorizado |
| **Objetivo** | Registrar informações complementares de um host e consultar os gerentes da aplicação |
| **Requisitos relacionados** | RF29, RF30, RF31 |
| **Pré-condições** | Aplicação iniciada; para criar uma anotação, host existente no inventário |

## Fluxo principal — criar anotação

1. O operador informa o IP do host e o conteúdo da anotação.
2. O sistema confirma que o host existe e que o conteúdo não está vazio.
3. O sistema persiste a anotação associada ao host.
4. O sistema retorna a anotação cadastrada com seu identificador.

## Fluxos alternativos

- **Consultar:** o operador solicita uma anotação pelo identificador ou lista anotações, opcionalmente filtrando pelo IP do host.
- **Atualizar:** o operador informa identificador e novo conteúdo; o sistema valida o conteúdo e persiste a alteração.
- **Excluir:** o operador informa o identificador; o sistema remove a anotação. Se o host for removido, as anotações vinculadas são removidas junto.
- **Obter gerentes:** um cliente da aplicação solicita a fachada única e recebe acesso aos gerentes configurados para a aplicação.
- **Contar entidades:** o cliente solicita a contagem e o sistema soma hosts, usuários e anotações cadastrados.

## Exceções

- Host não cadastrado: a anotação não é criada.
- Conteúdo vazio: criação ou atualização rejeitada.
- Identificador inexistente: consulta e atualização informam que a anotação não foi encontrada; exclusão retorna `false`.

## Pós-condições

- A anotação criada, alterada ou removida fica refletida na persistência SQLite.
- A contagem inclui hosts, usuários e anotações; evidências de auditoria não entram nessa contagem.
